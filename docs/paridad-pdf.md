# Sytue PDF — parity with iLovePDF Premium and Foxit PDF Editor Pro

This table exists because saying “it has parity” by hand is not good enough: it has to be
possible to **check it feature by feature**, and to know which ones are missing and why. Each row
points to the file that implements it, so anyone in doubt can open it.

It is compared against the **paid editions**: iLovePDF Premium (the list of
tools on its website) and Foxit PDF Editor Pro (its Standard/Pro comparison).

Updated: **2026-10-03**.

<a id="cómo-se-lee"></a>

## How to read it

- **✓** — done and wired all the way to the button: engine, endpoint and interface.
- **◐** — the engine does it, but part of the path is missing (we say which).
- **✗** — not there. It comes with the reason, which is sometimes “it will not be done”.

A feature that only exists in the engine does NOT count as done: the house
rule is that a feature that is implemented but not switched on is a bug.

## What is really missing, and why

1. ~~**JPEG 2000**~~ **Done on 2026-08-18** (`pdfjpx*.go`). It was written because
   the most expensive piece was already there: the JBIG2 MQ arithmetic decoder is THE
   SAME one this standard requires. Declared scope —one tile, no custom
   precincts— and whatever falls outside it is REJECTED with its reason, without painting noise.
2. ~~**Tagging a PDF/UA.**~~ **Done on 2026-10-04** for what Sytue exports from
   Docus (the owner's decision that day), in six pieces: embedded fonts
   (`platform/pkg/pdffuente`), structural markup (`platform/pkg/pdfdoc`), real tables and
   images with `/Alt`, validation (`pdfdoc/uacheck` plus veraPDF as a control), integration
   («PDF accesible» (Accessible PDF) in Archivo (File), on by default) and measurements. Details in
   [architecture.md](architecture.md#pdf-accesible).
   - **What remains undone, on purpose:** tagging a third-party PDF that did not come
     tagged. It requires guessing the reading order of a layout, and getting it wrong produces
     a document that claims to be accessible and reads backwards.
   - **Validation:** the test document corpus and the Docus export pass veraPDF
     1.30.2 (PDF/UA-1 profile) with no errors. Manual testing with NVDA and VoiceOver remains,
     which cannot be automated.
3. ~~**Double-clicking a `.pdf` on the desktop.**~~ **Done on 2026-08-17**
   (in the Wails shell, retired on 2026-09-23; in Fyne it is declared by `extensiones` in
   `apps/fyne/cmd/certipdf/FyneApp.toml`): the file requested by the OS travels over the
   loopback bridge, ONCE and only with the extensions the product declares. On Linux
   the type is **declared but not set as default**: anyone who has another reader does not
   want installing the suite to change it without asking.
4. **HTML to PDF.** It needs a web layout engine; it does not fit the
   invariant of zero new dependencies.

## Cost of redacting images (measured 2026-10-04)

Probe `TestMedirRedaccionDeImagenes` (`SYTUE_PDF_MEDIR_REDACCION=1`), ARM64 front-end server,
with a quarter of the image inside the area:

| Image                                       | Time   | Allocated memory |
| ------------------------------------------- | ------ | ---------------- |
| RGB Flate 4000×3000 (12 Mpx)                | 6.1 s  | 418 MiB          |
| JPEG 4000×3000 (12 Mpx)                     | 4.8 s  | 174 MiB          |
| Grayscale 4960×3508 (17 Mpx, A4 at 600 dpi) | 7.3 s  | 349 MiB          |
| RGB Flate 6000×4000 (24 Mpx, cap)           | 11.5 s | 825 MiB          |

The 24 Mpx per-image cap bounds the worst case at ~12 s and ~0.8 GiB.

## Cost of the accessible PDF (measured 2026-10-04)

Probe `TestMedirPDFAccesible` (`SYTUE_PDF_MEDIR_UA=1`), ARM64 front-end server **under load ~40-55**
(the times are an upper bound and noisy; size and allocated memory are deterministic).
Median of 7 exports, compared with the simple PDF from `pdfsimple`:

| Document                           | Pages | Accessible: size | time   | memory   | Simple: size       | time   | memory   | Fonts in the accessible one |
| ---------------------------------- | ----- | ---------------- | ------ | -------- | ------------------ | ------ | -------- | --------------------------- |
| One line                           | 1     | 13.9 KB          | 1.1 ms | 1.3 MiB  | 1.0 KB             | 0.1 ms | 0.1 MiB  | 2 faces, 8.1 KB (58 %)      |
| Typical report (6 sections, table) | 5     | 39.6 KB          | 105 ms | 5.0 MiB  | 24.9 KB            | 5 ms   | 1.0 MiB  | 2 faces, 12.6 KB (31 %)     |
| Typical with an 800×500 image      | 5     | 415 KB           | 351 ms | 16.1 MiB | 24.9 KB (no image) | 22 ms  | 1.7 MiB  | 2 faces, 12.6 KB (3 %)      |
| Typical with Greek and Cyrillic    | 5     | 52.9 KB          | 49 ms  | 5.3 MiB  | 25.0 KB (with “?”) | 2 ms   | 1.0 MiB  | 3 faces, 24.0 KB (45 %)     |
| Long (120 sections)                | 75    | 233 KB           | 1.2 s  | 69.7 MiB | 464 KB             | 271 ms | 16.6 MiB | 2 faces, 13.4 KB (5 %)      |

What the numbers say:

- **Embedding fonts costs ~6 KB per face used** (a fixed minimum of 4 KB: complete `loca` and `hmtx`,
  which compress well, plus the outlines of the glyphs used). An ordinary report
  uses two faces (regular and bold): 12.6 KB. The fallback (Liberation Sans) only comes in if the
  text asks for it, and adds ~11 KB. Reading the eight faces from the binary happens once per process: 45 ms.
- **The fixed cost is ~13 KB** (one line: 13.9 KB versus 1 KB): fonts, XMP and structure.
  From about 40 pages on, the accessible one weighs **less** than the simple one, because it compresses the
  content and the simple one does not (75 pages: 233 KB versus 464 KB).
- **Time and memory**: on the order of 20 times the simple one for a typical document (laying out with
  real metrics, compressing, structure), in absolute terms tens of milliseconds and
  5 MiB. Two fixes came out of measuring and ship in this piece: the per-font `cmap` cache
  (without it every character walked the table with a new buffer) and a single compressor per
  file. Before and after, allocated memory: typical 39.6 → 5.0 MiB; 75 pages
  654.6 → 69.7 MiB.
- **An image outweighs everything else**: a PNG is rewritten as RGB with Flate (the one in the
  test is noise, the worst case: 375 KB); a JPEG passes through as is. The cap is 16 Mpx per image.

## Web and desktop

Web and desktop share the product contract and the PDF APIs. The desktop client
is a native Fyne view (ADR-0024), not a wrapper around `docs.sytue.eu/pdf`; each capability
is implemented and recorded in the parity matrix in the same wave. What the desktop adds
on its own:

|                                      | Status                                                                        |
| ------------------------------------ | ----------------------------------------------------------------------------- |
| Its own binary, icon and installer   | ✓ `apps/fyne/cmd/certipdf`                                                    |
| Native menu with «Abrir…» (Open…)    | the Wails shell had it, retired on 2026-09-23; in Fyne, unverified            |
| Deep link `sytue-pdf://`             | ✓ registered on all three systems                                             |
| External links in the system browser | ✓ explicit opening through the native integration                             |
| Mobile (App Store / Play)            | ✓ `apps/mobile/suite/products.ts`                                             |
| Association with `.pdf`              | ✓ declared, without stealing any existing one; the file reaches the Fyne view |
